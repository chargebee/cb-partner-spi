# OpenPay SPI Integration

The **OpenPay Service Provider Interface (SPI)** enables seamless communication between Chargebee and external payment gateways through a standardized interface.

You can refer to the spec file for this SPI [here](https://github.com/chargebee/cb-partner-spi/blob/main/spec/spi/openapi_openpay.yml).

Chargebee leverages external payment services to execute the following operations efficiently:

### 1. Payment Method Management
Create, update, retrieve, confirm, and delete payment methods, along with associated customer profiles, in the payment gateway.

### 2. Payment Processing
Process, verify, capture, refund, and void payments through the configured gateway. Retrieve a payment to sync the latest transaction state.

### 3. Gateway Setup
Set up and validate gateway account credentials, supporting both direct gateway integrations and orchestrator-based setups.

## The Role of the OpenPay Adapter

Chargebee maintains a built-in adapter layer that connects to a range of supported payment gateways out of the box. Most merchants do not need to implement anything—Chargebee handles the communication with the payment gateway on their behalf.

## Building a Custom OpenPay Adapter

In some cases, you may want to go beyond the built-in adapter. Implementing the OpenPay SPI lets you build a custom adapter if any of the following apply:

- **Unsupported Gateway:**
  The payment gateway you want to use is not yet supported by Chargebee. You can implement an adapter yourself to bring that gateway into the Chargebee ecosystem.

- **Payment Gateway Provider:**
  You are a gateway provider and want to offer a native, certified integration with Chargebee for your merchants.

- **Custom Adapter for an Existing Gateway:**
  You need behavior that differs from Chargebee's built-in adapter—such as custom routing logic, orchestrator-specific handling, or additional gateway parameters.

- **System Integrator:**
  You are building a connector on behalf of a merchant or gateway, bridging a payment service with Chargebee.

## Gateway credentials and setup parameters

Before an OpenPay SPI integration is onboarded, share the gateway credential fields the merchant must fill in when connecting the gateway. Describe every field as follows:

- **Field name.** A unique name for the field. Chargebee sends this same name on every API request inside the `gateway_credentials` object of the `Authorization` header.
- **Type.** `plain_text`, `secret`, or `list`.
- **Allowed values.** When the type is `list`, include the allowed values.
- **Required or optional.** Whether the merchant must provide the field.

| Field name | Type | Allowed values | Required |
| --- | --- | --- | --- |
| `api_key` | `secret` | — | Required |
| `merchant_id` | `plain_text` | — | Required |
| `environment` | `list` | `sandbox`, `live` | Optional |

The names above show the format to share. Replace them with the fields your gateway actually needs.

The `Authorization` header is a JSON object. Chargebee base64-encodes that JSON and sends it as a Bearer token. It carries `gateway_credentials` and, after gateway setup, `set_up_parameters`.

### Gateway setup

When a merchant connects the gateway and submits the credential fields, Chargebee calls [Set up gateway connection](../endpoints/v1/setup-gateway) with those credentials.

If the adapter needs to assign a unique id for the connection, or keep any other metadata for later calls, return that data in the Gateway Setup response. Chargebee then sends those values on every subsequent API request as `set_up_parameters` in the same `Authorization` JSON, alongside `gateway_credentials`.

```json
{
  "gateway_credentials": {
    "api_key": "<value the merchant entered>",
    "merchant_id": "<value the merchant entered>"
  },
  "set_up_parameters": {
    "connection_id": "<id returned by gateway setup>"
  }
}
```

```
Authorization: Bearer <base64-encoded-JSON>
```

## PCI DSS Compliance

The provider that implements the OpenPay SPI (the "Adapter Provider"), whether a payment gateway, orchestrator, or system integrator, is solely responsible for the collection, transmission, processing, and storage of payment method data (such as card numbers, bank account details, and other sensitive authentication data) within its own environment.

By integrating with Chargebee through the OpenPay SPI, the Adapter Provider acknowledges and agrees that:

- **PCI DSS responsibility.** The Adapter Provider must be PCI DSS compliant at the level applicable to its role and must maintain that compliance for as long as it is integrated with Chargebee. On request, it must provide evidence of compliance, such as a current Attestation of Compliance (AOC).
- **Payment method collection.** Where the Adapter Provider collects payment methods (for example, through hosted fields, hosted payment pages, SDKs, or APIs), it is responsible for securing that collection flow.
- **Tokenization.** The Adapter Provider should return tokens or references to Chargebee, not sensitive cardholder data. Sensitive authentication data must never be stored after authorization.
- **Security of credentials and data.** The Adapter Provider is responsible for securing the gateway credentials and any payment data it handles, and for notifying Chargebee promptly of any security incident affecting that data.
